# Limitaciones y bloqueos explícitos

1. Prototipo de investigación, sin validación clínica, autorización NASA, datos reales o sensores conectados. Todas las decisiones operacionales y terapéuticas bloqueadas. La API conserva datos no sintéticos, pero no los evalúa con los comparadores de simulación.
2. Los 15 comparadores implementan los JSON suministrados; no son 15 protocolos clínicos aprobados. No se ejecuta el inventario reconstruido ni reglas numéricas ajenas a los objetos originales. Ortostatismo requiere misión; el standing test se bloquea en microgravedad.
3. El cuerpo principal de evidencia son resúmenes/JSON publicados y enlaces, no una biblioteca local de PDFs clínicamente revisados. S27 y otros problemas de procedencia constan en reconciliación. Se necesita revisión independiente de cada fuente, método y alcance.
4. Calidad depende del rango técnico, caducidad y calibración registrados por un operador confiable. No verifica certificados de fabricante ni señal fisiológica cruda. `synthetic` y métodos son declaraciones del laboratorio de simulación; no demuestran validez física.
5. El promedio CO2 admite solo intervalos con media declarada, misma variable/protocolo/compartimento/dispositivo y cobertura completa. No admite interpolación, frecuencia implícita, ventana parcial, stitching multisensor ni filtro validado de datos crudos. Las tasas de presión requieren métricas de evento suministradas; no hay derivador validado de señales.
6. Baseline requiere observaciones preflight distintas y protocolo/método/sitio comparables; mínimo configurable, sin valor clínico por defecto. No hay modelo de cross-calibration, corrección por aprendizaje o recuperación validada. MAD cero y varianza cero no producen z-score infinito. Estadística siempre RESEARCH_ONLY.
7. Hipótesis y observaciones son entradas humanas, no diagnósticos del motor. DIAGNOSIS, TRIAGE y AUTHORIZED_ACTION bloqueados. Cambiar un episodio a RECOVERY/CLOSED documenta una decisión humana; no certifica recuperación ni aptitud. Follow-ups son planes/registros, sin scheduler de alarmas en segundo plano.
8. Autorización por token y rol configurados exclusivamente en servidor; no existe emisión de permisos clínicos porque faltan protocolos revisados. No hay PKI, MFA, firma médica, revocación con lista de certificados ni integración institucional. Hashes en tokens.json y secretos separados en client-credentials.json; ACL aplicada a usuario actual, SYSTEM y Administrators. Recarga por petición, disabled y expires_at permiten revocación/caducidad; no entregar token de escritura al LLM.
9. SQLite no está cifrada. No usar datos sensibles de tripulantes hasta completar privacidad, cifrado y despliegue seguro. v0.2 incorpora alcance por persona/misión y proyección RAG mínima; reader ya no accede a registros completos. Tokens administrativos de ejemplo siguen teniendo wildcard y deben restringirse. La cadena hash no resiste un administrador host malicioso.
10. Uso local de baja escala: consultas recorren registros; falta paginación general, retención, migraciones futuras, backup/restore operativo y pruebas de carga. El servidor está ligado a loopback; no es despliegue multitenant.
11. Wheels incluidos para Windows x64/Python 3.13. El código declara Python >=3.11, pero no se probaron otras combinaciones. Instalación offline requiere Python compatible ya instalado. Aviso de deprecación Starlette/httpx en TestClient permanece; no hubo fallos. No se cambió dependencia solo para ocultar el aviso.
12. Datasets: solo descriptores, sin adaptadores científicos específicos ni datos brutos, etiquetas diagnósticas o validación prospectiva. No hay GUI, LLM real, RAG vectorial, optimizador espacial, actuación de ECLSS ni dispensación de fármacos.
